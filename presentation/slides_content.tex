\section{Introduction}
\begin{frame}{Project Objectives}
\small
\begin{itemize}[<+->]
  \item Build a trajectory classifier for a 7-DoF peg-in-hole task with \textbf{3 classes}.
  \item Use LSTM architecture.
  \item Deliver two outcomes:
  \begin{itemize}[<+->]
    \item strong performance on the internal test split,
    \item Analysis of \textbf{feature influence} on performance.
  \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{Problem Framing}
\small
\begin{itemize}[<+->]
  \item Input: one full trajectory tensor \(\in \mathbb{R}^{150 \times 20}\).
  \item Output: one class label \(\in \{0,1,2\}\) for the complete sequence.
  \item Why sequence learning: class information is encoded in \textbf{temporal dynamics}, not only static snapshots.
  \item Evaluation context: internal split (train/val/test), plus compatibility with an external test set.
\end{itemize}
\end{frame}

\small

\begin{frame}{Preprocessing Pipeline}
\small
\begin{itemize}[<+->]
  \item Reproducibility: fixed random seed (\texttt{SEED=42}) for split and initialization.
  \item Split: \textbf{80/10/10} \(\Rightarrow\) train \(614\), val \(76\), test \(78\).
  \item Normalization: z-score computed on train only, then reused on val/test.
  \item Numerical stability: \(\sigma = 0\) replaced by small \(\epsilon\).
\end{itemize}
\vspace{-0.1em}
\[
\mathbf{x}_{norm} = \frac{\mathbf{x}-\boldsymbol{\mu}_{train}}{\boldsymbol{\sigma}_{train}+\epsilon}
\]
\vspace{-0.2em}

\section{Model}

\begin{frame}{Architecture and Training Setup}
\small
\begin{itemize}[<+->]
  \item Input tensor: \((\texttt{batch},n_{timesteps}= 150,n_{features}= 20)\).
  \item Backbone: \texttt{LSTM(num\_layers=2, hidden\_size=64, dropout=0.2)}.
  \item Classifier head: last hidden state \(\rightarrow\) \texttt{Linear(64,3)}.
  \item Loss and optimizer: \texttt{CrossEntropyLoss} + \texttt{Adam(lr=1e-3)}.
  \item Batch size: \(32\), \(40\) epochs.
  \item Stability: gradient clipping \(\|\nabla\|_{max}=1.0\).
\end{itemize}
\end{frame}

  \column{0.50\textwidth}

  \column{0.46\textwidth}

  \textbf{Observed issue}\\
  Large gradient spikes destabilize the parameter's updates.
  \vspace{0.2em}

\section{Conclusion}
\begin{frame}{Conclusion}
\small
\begin{itemize}[<+->]
  \item The final full-feature LSTM pipeline (2 layers, hidden 64, dropout, clipping) reaches top internal performance.
  \item Methodical ablation clarifies causality:
  \begin{itemize}[<+->]
    \item The peg's pose and orientation are highly informative,
    \item The peg velocity is informative but optimization-sensitive,
    \item The hole's pose/orientation alone is not discriminative here.
  \end{itemize}
  \item Good accuracy comes from both \textbf{signal selection} and \textbf{stable optimization}, not from architecture choice alone.
\end{itemize}
\end{frame}

\section{Backup (Q\&A)}

\begin{frame}{Backup: Why 2 LSTM Layers and Hidden Size 64?}
\small
\begin{itemize}[<+->]
  \item The selected configuration is \texttt{num\_layers=2, hidden\_size=64}.
  \item It gave the best stability/performance tradeoff in our controlled runs.
  \item A stronger baseline (hidden size 100) showed weaker behavior in this project context.
  \item With \(768\) trajectories and \(150\) timesteps, over-capacity increases instability/overfitting risk.
  \item Two recurrent layers keep modeling depth while staying computationally light.
\end{itemize}
\end{frame}

\begin{frame}{Backup: Why Gradient Clipping at 1.0?}
\begin{columns}[t,onlytextwidth]
  \column{0.50\textwidth}
  \includegraphics[width=0.84\linewidth]{gradient_explosion.png}
  {\tiny Observed gradient norm spikes before stabilization.}
  \column{0.46\textwidth}
  \tiny
  \textbf{Rule used}\\
  \texttt{clip\_grad\_norm\_(..., 1.0)}.
  \vspace{0.2em}

  \textbf{Reasoning}\\
  - recurrent training showed large norm spikes\\
  - only large gradients are rescaled
  \vspace{0.2em}

  \textbf{Observed effect}\\
  stable late-epoch behavior and no final divergence.
\end{columns}
\end{frame}

\begin{frame}{Backup: Feature Interpretation (Physical View)}
\small
\begin{itemize}[<+->]
  \item \textbf{Peg pose/orientation (0:7)}: directly tracks insertion geometry and trajectory signature.
  \item \textbf{Peg velocity (7:13)}: informative but noisier; requires longer optimization to fully separate classes.
  \item \textbf{Hole pose/orientation (13:20)}: near-constant in these trajectories, so weak discriminative power alone.
  \item Ablation behavior is therefore physically coherent with the task dynamics.
\end{itemize}
\end{frame}

\begin{frame}{Backup: Validity Limits and Expected Jury Questions}
\small
\begin{itemize}[<+->]
  \item Internal test set size is \(78\) trajectories: strong result, but still finite-sample uncertainty.
  \item Current evidence is mostly split-based; class-wise confusion details can be extended.
  \item Single-seed reporting is reproducible but not a full multi-seed robustness study.
  \item Final external hidden test remains the decisive out-of-distribution validation.
  \item Data leakage risk was mitigated by train-only normalization statistics.
\end{itemize}
\end{frame}

\begin{frame}{Backup: Why Not GRU or Transformer (Yet)?}
\small
\begin{itemize}[<+->]
  \item \textbf{Scope fit}: assignment asks for an LSTM trajectory classifier and feature-impact analysis.
  \item \textbf{Data regime}: \(768\) sequences is moderate; LSTM is sample-efficient for this scale.
  \item \textbf{Sequence length}: \(150\) steps does not force transformer-scale context handling.
  \item \textbf{Engineering tradeoff}: LSTM gave high accuracy with interpretable/stable training controls.
  \item GRU/Transformer remain valid extension baselines for future comparison.
\end{itemize}
\end{frame}

\begin{frame}{Backup: LSTM}
\small
\begin{itemize}[<+->]
  \item Reminder: vanilla RNNs are sensitive to vanishing/exploding gradients through BPTT.
  \item LSTM uses gated memory to control information flow and preserve useful long-range signals.
\end{itemize}
\vspace{-0.2em}
\[
i_t,f_t,o_t=\sigma(\cdot),\quad \tilde{c}_t=\tanh(\cdot),\quad
c_t=f_t\odot c_{t-1}+i_t\odot \tilde{c}_t
\]
\vspace{-0.6em}
\small
\begin{itemize}[<+->]
  \item This architecture matches the project setting: long trajectories (\(150\) steps) with dynamic class signatures.
\end{itemize}
